## 一、细则体例（七段必备）

每一份新细则统一按以下七段成文；**内容不足就写「本环节无此项」，不硬凑制度**：

| 段 | 必写内容 | 体例依据 |
|---|---|---|
| 1. 目的 | 本环节要解决的管理问题、适用范围与边界；不写大段理念 | 1399《招聘管理制度（总则）》把职责、对象、时限写成可执行条款（主表序号 26） |
| 2. 适用范围 | 机构、人员、岗位、例外情形；涉及「核心人才」时用 **M 序列管理干部＋P 序列核心岗位（在职口径按云库现查）** | 1483／1485 的适用范围原句；`TACIT-20261104-49`（不写人数） |
| 3. 职责分工 | 集团行政人事部／机构一把手／机构人事／业务负责人各自做什么；能落到审批人则不写「相关部门」 | 1465 离职程序、1466 核心人员离职面谈与评估报告的职责与时限（主表序号 30–31） |
| 4. 流程节点 | 触发条件 → 申请 → 审核 → 决策 → 执行 → 反馈；每个节点写责任人与时限 | 1490 试用期「考察—评估—答辩—公示」、1401 内部竞聘「笔试—面试—审定」（主表序号 4、27） |
| 5. 表单与工具 | 本环节真正需要的表单、检查表、面谈表、台账；表单只承载执行，不把表单写成另一套制度 | 1490 试用期考察表组、1465《离职申请表》《工作交接表》、1466《离职面谈表》《核心人员离职评估报告》 |
| 6. 记录与留痕 | 存放位置、审批记录、双方签字、报送对象、保存期限（未定就标待确认，不编年限） | 1466 双方签字入档、内网上传；1492/1495 绩效面谈与打分记录（主表序号 18–19） |
| 7. 附则 | 生效日期、解释部门、与既有制度的关系、引用文件的版本日 | 现行件均带落款日；04-E §5.2「后台 id／sort／落款日作附注」 |

**文首统一格式**：制度全名｜本草案编号｜版本状态（草案/试行/正式）｜拟生效日（未定写【待确认】）｜解释部门【待确认】。  
**引用统一格式**：`制度全名｜后台 id｜sort｜落款日｜正文来源`；iCloud 现行夹 8-N 主号仅作现行件的定位附注，**「细则N」不得单独引用**（04-E §5.2）。

## 二、命名与编号三套方案

### 方案 A（推荐）：保留 8 号母制度，六阶段用「8-Sx-yy」子卷号

| 项 | 草案 |
|---|---|
| 全名格式 | 《云上文旅集团干部管理制度·S1 人才吸引管理细则》（8-S1-01）；同阶段第二件依次 8-S1-02 |
| 号段 | S1–S6 各自从 01 起两位流水；工具表单用 `8-Sx-Fyy`（F=Form），不与细则号混排 |
| 与现行 14 件关系 | **不废止、不重编现行号**；旧件在映射附注里保留「iCloud 主号＋后台 id＋sort＋落款日」，新稿吸收哪件由后续逐件确认 |
| sort=11 | **保持空缺、不补号**（04-E 建议 6）；新子卷号天然避开 8-11，不拿空位当新稿号段 |
| 适用判断 | 最贴合「六个文件夹分阶段」的组织方式；新旧可共存，不会让 8-1 与 8-S1-01 被误认成同一号 |

**推荐点**：六阶段可直接检索，又保留现行 8 号的证据链；不用宣布旧件失效。

### 方案 B：六阶段独立成卷，现行 8 号并行保留

| 项 | 草案 |
|---|---|
| 全名格式 | 《云上文旅集团人才生命周期·S1 吸引管理细则》（TL-S1-01） |
| 号段 | TL-S1-01…TL-S6-01；工具表单 `TL-Sx-Fyy` |
| 与现行 14 件关系 | 8 号作为既有干部制度并行保留；六卷是新体系，**不默认替代 8 号**，重叠处只列「引用/吸收/并行」 |
| sort=11 | 旧 8 号空缺原样保留；新 TL 号段不使用 sort，不补旧号 |
| 适用判断 | 若要另起一套覆盖全生命周期的制度体系，边界最干净；但与 8 号重复面最大，须先拍「并行还是替代」 |

**代价**：新命名空间会增加「8 号干部制度 vs TL 生命周期制度」两套口径的维护成本，不作为默认。

### 方案 C（最小改动）：仍用 8 号连续流水，阶段只作分册标题

| 项 | 草案 |
|---|---|
| 全名格式 | 《云上文旅集团干部管理制度·人才吸引管理细则》（8-15），下一件 8-16 |
| 号段 | 从 8-15 起向后顺延；工具表单 `8-15-F01` |
| 与现行 14 件关系 | 现行 8-0～8-14 全部保留；新增件只是 8 号扩编，不重排、不替换 |
| sort=11 | 仍为空缺历史位；**不得把新细则放到 8-11**，新流水从 8-15 起 |
| 适用判断 | 改动最小、最贴近现行编号；但阶段语义只能靠标题，不利于按 S1–S6 机器归集 |

**取舍建议**：A 优先；若维护者要求完全脱离 8 号再选 B；若只要求少改编号规则可选 C。**不要为填补 sort=11 而选号。**

## 四、敏感条款与对外文案边界

1. 招聘/甄选条件中涉及**年龄、籍贯、婚育、学历一刀切、特定人群占比**的内容，先列【待确认】，**不得直接复制进新稿或任何对外模板**；主表 29（1403）只可作内部核对源。
2. 储备干部选拔中涉及**地域、婚育等个人条件**的表述，同样先标敏感待确认（1853 相关条款只作源件，不转录）。
3. 激励金额、津贴比例、处罚金额可作制度条款研究，但**不放进面向普通读者的宣传稿、海报或工具模板首页**；若新稿正文确需保留，走维护者确认。
4. 面试官名单、个人姓名、身份证、联系方式、个人薪资明细一律不转录；本草案不写人数、不输出个人数据。
5. 所有「旧件是否继续有效」均留维护者确认位；新稿不得借整合名义静默废止旧件。
